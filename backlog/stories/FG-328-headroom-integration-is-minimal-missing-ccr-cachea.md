**Current forge integration:**

  - CCR: ENABLED (tool_injection, response_handling, context_tracking, proactive_expansion)

- ✅ **Agents route through proxy** (compression_mode='proxy' default, spawn.ts sets ANTHROPIC_BASE_URL)
- ✅ **Orchestrator routes through proxy** (forge claude checks proxy health, sets ANTHROPIC_BASE_URL)

**Originally listed as "missing" but actually ENABLED in proxy:**

1. **CCR (Content-Compressed Representation)** ✅
   - Proxy stores originals and handles headroom_retrieve automatically
   - No additional forge integration needed

2. **CacheAligner** ✅
   - Proxy detects dynamic content and segregates to tail for better KV cache hits
   - Normalizes whitespace, collapses blank lines
   - Automatically applied to all requests

3. **ContentRouter** ✅
   - Proxy auto-detects JSON/code/text and picks SmartCrusher/CodeCompressor/Kompress
   - No forge code changes needed

4. **Hooks & lifecycle events** ⏸️
   - Proxy doesn't expose hook configuration via CLI
   - Would require custom proxy config file (not currently generated by forge)

5. **Advanced config** ⏸️
   - Proxy uses defaults; no ToolCrusherConfig/RollingWindowConfig/ScoringWeights tuning
   - Could be added via config file if ROI justifies it

6. **IntelligentContext** ✅
   - Built into proxy's compression pipeline
   - Score-based context fitting happens automatically

7. **Cross-agent memory** ⏸️
   - Proxy supports this but forge doesn't leverage it yet
   - Would require shared context store across invocations

8. **Image compression** ⏸️
   - Proxy supports it but forge doesn't send images yet
   - Blocked on browser-tools screenshot integration

9. **MCP server mode** ❌
   - Not needed — proxy mode handles compression transparently
   - Agents don't need explicit compress/retrieve tools
