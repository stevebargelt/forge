**Review-flow mechanics learned the hard way (all cost a round this session):**

- `--evaluated-no-drift` and `--add-lens` are **mutually exclusive** on `forge review start` — a widening IS a drift classification, so passing both is refused.
- The `--acceptance` file is a **bare JSON array** of `{ref, verdict, evidence}`, not an object with a `claims` key. `verdict` is `met` | `unmet` | `unproven`; only `met` requires structured evidence.
- The evidence validator **splits `test_name` on `;`**, so a cited test whose name contains a semicolon never matches its own runner output and reads as `not_executed`. Cite a semicolon-free test name, or use `replayed_reproduction` instead.
- Forge-on-forge: `forge invoke` is structurally REFUSED against the forge checkout (FG-612, no isolated workspace), but pipeline/workflow dispatch is fine because it provisions worktrees. Do implementation invokes in a disposable clone with `--project`.
- A changed path owned by no lens scope blocks `confirm_contract` — the docs cycle's own committed prose needs `docs/` inside a lens scope or the next pass refuses.
